# Localization

Read before touching `src/plugins/i18n.ts`, `src/plugins/vuetify.ts` locales, `SupportedLocales`, or `config/onLocaleChange`.

- Locale files and codes are **BCP 47, hyphenated** (`pt-BR`, `zh-TW`) — `pt_BR` makes `Intl`
  throw. Weblate must use the same style. Never edit non-English locale files directly
- `SupportedLocales` (`src/globals.ts`) is hand-maintained with native labels; a locale file
  without an entry (`sv`, `th`, `zh-TW`) exists for Weblate but isn't selectable
- `src/plugins/vuetify.ts`'s `locales` map is keyed by **Fluidd** code and doubles as the code
  translation (`zh-CN` → `zh-Hans`, `zh-HK`/`zh-TW` → `zh-Hant`, `pt-BR` → `pt`); a missing key
  leaves Vuetify on `en`.
  `loadVuetifyLocaleAsync` must `Vue.set` into `lang.locales` **before** assigning `lang.current`
  (the `current` write re-renders). These `import()`s don't code-split — Vuetify's default preset
  imports the whole locale barrel
- `loadLocaleMessagesAsync(locale?)` defaults to `getStartingLocale()`, guards on
  `i18n.availableLocales`, and on a failed import logs and keeps the current locale.
  `getStartingLocale` walks `navigator.languages` (full code, then bare language), then
  `VUE_APP_I18N_LOCALE`, then `en`
- `config/onLocaleChange` holds `Waits.onLoadLanguage` (drives the spinner in `GeneralSettings`)
